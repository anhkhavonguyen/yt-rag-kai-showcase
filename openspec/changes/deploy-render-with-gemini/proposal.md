# Proposal

## Why

The project owner has no OpenAI key and no billed cloud account, so yt-rag can't run anywhere today. Embeddings are hardwired to OpenAI, and deployment assumes Cloud Run, which needs billing. A free host plus a free model provider would let the owner test the RAG pipeline end to end on a public URL at no cost. The new GitHub Actions CI (`add-github-actions-ci`) can gate those deploys.

## What Changes

- **Configurable OpenAI-compatible provider.** A new `OPENAI_BASE_URL` setting points the existing OpenAI clients (chat and embeddings) at any OpenAI-compatible endpoint. The target is Google Gemini's free tier, using `gemini-3.5-flash` for chat and `gemini-embedding-2` for embeddings, but no provider is hardcoded. With no base URL set, behaviour is unchanged (api.openai.com).
- **Fixed embedding size.** Every embedding the app stores or searches with has exactly `EMBEDDING_DIMENSIONS` (default 1536) values. This matches the existing `VECTOR(1536)` Supabase schema, which pgvector can index (index limit 2000). Gemini returns 3072 dimensions by default.
- **Fallback answer when the model is unavailable.** If the chat model call fails (for example, the free-tier quota is used up), `/answer` returns the best-matching retrieved passages with citations instead of an error message. The response reports which mode produced the answer.
- **Admin token for `/seed`.** When `SEED_TOKEN` is set, `/seed` rejects requests that don't present it. The chat page's document editor asks for the token, and the CLI chatbot sends it from its environment. When the token isn't set, as in local development, `/seed` stays open as today.
- **Free hosting on Render.** A `render.yaml` blueprint deploys the existing Dockerfile to a Render free web service (512 MB RAM, sleeps after 15 minutes idle), with `/healthz` as the health check. Deploys run only after the CI checks on `main` pass. Secrets are entered in the Render dashboard and never committed. `SEED_TOKEN` is generated by Render.
- **Docs.** `.env.example`, the README and `DEPLOYMENT.md` describe the free setup (Gemini key, free Supabase project, Render blueprint) in place of the Cloud Run guide. The README gets a "Deploy to Render" button.

## Capabilities

### New Capabilities
- `model-provider`: which OpenAI-compatible endpoint and models the app uses for chat and embeddings, and the guarantee about embedding size.
- `question-answering`: how `/answer` responds, including the fallback when the language model is unavailable and how the response reports the answer mode.
- `knowledge-base-seeding`: who may change the knowledge base through `/seed`, and how the chat page and CLI provide the admin token.
- `deployment`: how the app is deployed to the free host, including build source, port, health check, CI-gated deploys and secret handling.

## Impact

- **Code**:
  - `app/core/config.py`: new settings `openai_base_url`, `seed_token`, and use of `embedding_dimensions`.
  - `app/services/embedding.py`: base URL, dimension request and enforcement, batching.
  - `app/services/chat.py`: base URL.
  - `app/services/rag.py`: fallback answer and answer mode.
  - `app/main.py` and `app/models/responses.py`: token check on `/seed`, `answer_mode` in the debug info.
  - `static/chat.html`: token prompt on 401.
  - `chatbot.py`: sends the token.
- **API**:
  - `/seed` can return **401** when a token is configured. This is a breaking change only for deployments that set `SEED_TOKEN`; local development behaves as before.
  - `/answer` adds `debug.answer_mode` (additive).
- **Data**: the Supabase schema is unchanged (`VECTOR(1536)`). Embeddings from different models aren't comparable, so switching to Gemini needs a re-seed. The 4 default documents give 4 chunks, which is one embedding request.
- **New files**: `render.yaml`.
- **Tests**: new and updated tests under `tests/` for the provider settings, embedding size, fallback answer and seed token. They run in the existing CI with no real keys.
- **Dependencies**: none added. The existing `openai` SDK is used for Gemini via its OpenAI-compatible endpoint.
- **External accounts (owner, all free tiers)**: a Google AI Studio API key, a Supabase project with `sql/init_supabase.sql` applied, and a Render account linked to the GitHub repo.
- **Depends on**: `add-github-actions-ci` merged to `main`, because Render deploys only after CI checks pass.
