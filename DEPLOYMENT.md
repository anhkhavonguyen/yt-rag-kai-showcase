# Free Deployment Guide (Render + Gemini + Supabase)

This guide deploys yt-rag on free tiers only, and no step asks for a payment method:

| Part | Service | Free tier |
|---|---|---|
| App (this repo's `Dockerfile`) | [Render](https://render.com) web service | 512 MB RAM, sleeps after 15 min idle |
| Chat model + embeddings | [Google Gemini API](https://aistudio.google.com) (OpenAI-compatible endpoint) | rate- and daily-limited |
| Vector database | [Supabase](https://supabase.com) Postgres + pgvector | small projects, pauses when inactive |

Render deploys the service from [`render.yaml`](render.yaml). Every commit to `main` is deployed **only after the GitHub Actions CI checks pass**.

## 1. Get a Gemini API key

1. Sign in to [Google AI Studio](https://aistudio.google.com) and create an API key.
2. Keep it for step 3. It goes into `OPENAI_API_KEY`, because the app talks to Gemini through its OpenAI-compatible API.

> On the free tier, Google may use your prompts and documents to improve its products. Only seed documents you're comfortable sharing.

## 2. Create the Supabase database

1. Create a free project at [supabase.com](https://supabase.com). Pick a region near the Render region in `render.yaml` (`singapore` by default, so choose Southeast Asia (Singapore)).
2. Open **SQL Editor**, paste all of [`sql/init_supabase.sql`](sql/init_supabase.sql) and run it. The last row should say the database is ready.
3. From the project's API settings, copy:
   - the **Project URL**, for `SUPABASE_URL`;
   - the **publishable** key (`sb_publishable_...`) or legacy **anon** key, for `SUPABASE_ANON_KEY`;
   - the **secret** key (`sb_secret_...`) or legacy **service_role** key, for `SUPABASE_SERVICE_ROLE_KEY`.

   Don't put the publishable key in `SUPABASE_SERVICE_ROLE_KEY`. Reading still works, but seeding then fails with *"new row violates row-level security policy for table rag_chunks"*. If the new-style keys don't work and `/healthz` reports the database as disconnected, use the keys under **Legacy API keys** instead.

## 3. Create the Render service

1. Sign in to [Render](https://render.com) with GitHub.
2. Choose **New → Blueprint** and select this repository. Render reads `render.yaml` and previews **one web service, `yt-rag`, on the Free plan**, built from `./Dockerfile`.
3. Render asks for the four secrets:

   | Variable | Value |
   |---|---|
   | `OPENAI_API_KEY` | your Gemini API key from step 1 |
   | `SUPABASE_URL` | Project URL from step 2 |
   | `SUPABASE_ANON_KEY` | anon key from step 2 |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key from step 2 |

   Everything else (`OPENAI_BASE_URL`, `OPENAI_CHAT_MODEL`, `OPENAI_EMBED_MODEL`, `EMBEDDING_*`, `ENVIRONMENT`) is preset in `render.yaml`. `SEED_TOKEN` is generated by Render.
4. Apply. The first build takes a few minutes. Then check:

   ```bash
   curl https://<your-service>.onrender.com/healthz
   # {"status":"ok","database_connected":true}
   ```

The region can't be changed after the service is created. To use another region, edit `region:` in `render.yaml` before step 3.

## 4. Seed the knowledge base

`/seed` is protected by an admin token. Find it in Render under **yt-rag → Environment → `SEED_TOKEN`**.

- **Admin page:** open `https://<your-service>.onrender.com/admin` and enter the token. The page remembers it for that browser tab only. Edit the documents if you like, then click **Save**.
- **curl:**

  ```bash
  curl -X POST https://<your-service>.onrender.com/seed \
    -H "Authorization: Bearer <SEED_TOKEN>"
  ```

- **CLI chatbot.** It needs `pip install requests rich`. Run it, then type `/seed`:

  ```bash
  SEED_TOKEN=<SEED_TOKEN> python chatbot.py https://<your-service>.onrender.com
  ```

Without the token, `/seed` returns `401`, and the admin page asks for the token when it opens. Everything else (`/chat`, `/answer`, `/healthz`, `/documents`) is public. The customer chat page has no editor and no link to `/admin`.

## 5. Ask a question

```bash
curl -X POST https://<your-service>.onrender.com/answer \
  -H "Content-Type: application/json" \
  -d '{"query": "What is your return policy?"}'
```

`debug.answer_mode` in the response tells you how the answer was produced:

| `answer_mode` | Meaning |
|---|---|
| `generated` | Gemini wrote the answer from the retrieved passages |
| `extractive` | The chat model was unavailable (e.g. free quota used up), so the best-matching passages are returned with citations |
| `no_results` | Nothing relevant was found. Seed the knowledge base first |
| `error` | The question couldn't be searched (e.g. the embedding quota is used up). Try again later |

## Good to know

- **Cold starts.** A free Render service sleeps after 15 minutes without traffic. The next request wakes it in about a minute; the browser shows a loading page, and the CLI or curl may time out, so retry. Render can also restart free services at any time.
- **Free-tier quotas.** Gemini limits requests per minute and per day. Seeding the 4 default documents takes one embedding request. When the chat quota runs out, answers fall back to `extractive`.
- **Supabase pausing.** Free projects pause after a period of inactivity. Resume yours from the Supabase dashboard.
- **Changing settings later.** Render asks for the secrets only when the Blueprint is first created. To change a key or model later, edit it in **yt-rag → Environment**. Saving redeploys the service.
- **Switching the embedding model.** Vectors from different models can't be compared. After changing `OPENAI_EMBED_MODEL`, seed **all** documents again (seeding overwrites chunks by `chunk_id`).
- **Embedding size.** The database column is `VECTOR(1536)`, so `EMBEDDING_DIMENSIONS` must stay `1536`. Longer vectors from the model are shortened and re-normalized automatically.

## Running locally with Gemini

Copy the Gemini block from [`.env.example`](.env.example) into your `.env`, add your Supabase values, then:

```bash
uvicorn main:app --reload --port 8000
```

## Paid alternative: Google Cloud Run

The same image runs on Cloud Run, but that needs a Google Cloud project with billing enabled. Deploy with `gcloud run deploy yt-rag --source . --allow-unauthenticated`, and set the same environment variables as `render.yaml`, including your own `SEED_TOKEN`.
