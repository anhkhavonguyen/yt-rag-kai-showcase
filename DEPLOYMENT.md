# Free Deployment Guide (Render + Gemini + Supabase)

This guide deploys yt-rag on free tiers only, and no step asks for a payment method:

| Part | Service | Free tier |
|---|---|---|
| App (this repo's `Dockerfile`) | [Render](https://render.com) web service | 512 MB RAM, sleeps after 15 min idle |
| Chat model + embeddings | [Google Gemini API](https://aistudio.google.com) (OpenAI-compatible endpoint) | rate- and daily-limited |
| Vector database | [Supabase](https://supabase.com) Postgres + pgvector | small projects, pauses when inactive |

Render deploys the service from [`render.yaml`](render.yaml). Every commit to `main` is deployed **only after the GitHub Actions CI checks pass**.

## 1. Get a Gemini API key

1. Sign in to [Google AI Studio](https://aistudio.google.com) and create an API key.
2. Keep it for step 3. It goes into `OPENAI_API_KEY`, because the app talks to Gemini through its OpenAI-compatible API.

> On the free tier, Google may use your prompts and documents to improve its products. Only seed documents you're comfortable sharing.

## 2. Create the Supabase database

1. Create a free project at [supabase.com](https://supabase.com). Pick a region near the Render region in `render.yaml` (`singapore` by default, so choose Southeast Asia (Singapore)).
2. Open **SQL Editor**, paste all of [`sql/init_supabase.sql`](sql/init_supabase.sql) and run it. The last row should say the database is ready.
3. From the project's API settings, copy:
   - the **Project URL**, for `SUPABASE_URL`;
   - the **publishable** key (`sb_publishable_...`) or legacy **anon** key, for `SUPABASE_ANON_KEY`;
   - the **secret** key (`sb_secret_...`) or legacy **service_role** key, for `SUPABASE_SERVICE_ROLE_KEY`.

   Don't put the publishable key in `SUPABASE_SERVICE_ROLE_KEY`. Reading still works, but seeding then fails with *"new row violates row-level security policy for table rag_chunks"*. If the new-style keys don't work and `/healthz` reports the database as disconnected, use the keys under **Legacy API keys** instead.

## 3. Create the Render service

1. Sign in to [Render](https://render.com) with GitHub.
2. Choose **New → Blueprint** and select this repository. Render reads `render.yaml` and previews **one web service, `yt-rag`, on the Free plan**, built from `./Dockerfile`.
3. Render asks for the four secrets:

   | Variable | Value |
   |---|---|
   | `OPENAI_API_KEY` | your Gemini API key from step 1 |
   | `SUPABASE_URL` | Project URL from step 2 |
   | `SUPABASE_ANON_KEY` | anon key from step 2 |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role key from step 2 |

   Everything else (`OPENAI_BASE_URL`, `OPENAI_CHAT_MODEL`, `OPENAI_EMBED_MODEL`, `EMBEDDING_*`, `ENVIRONMENT`) is preset in `render.yaml`. `SEED_TOKEN` is generated by Render.
4. Apply. The first build takes a few minutes. Then check:

   ```bash
   curl https://<your-service>.onrender.com/healthz
   # {"status":"ok","database_connected":true}
   ```

The region can't be changed after the service is created. To use another region, edit `region:` in `render.yaml` before step 3.

## 4. Seed the knowledge base

`/seed` is protected by an admin token. Find it in Render under **yt-rag → Environment → `SEED_TOKEN`**.

- **Admin page:** open `https://<your-service>.onrender.com/admin`. It sends you to the sign-in page, `/admin/login`. Sign in with the token. The session lasts 8 hours, or until you click **Sign out**; changing `SEED_TOKEN` ends every session. Edit the documents if you like, then click **Save**.
- **curl:**

  ```bash
  curl -X POST https://<your-service>.onrender.com/seed \
    -H "Authorization: Bearer <SEED_TOKEN>"
  ```

- **CLI chatbot.** It needs `pip install requests rich`. Run it, then type `/seed`:

  ```bash
  SEED_TOKEN=<SEED_TOKEN> python chatbot.py https://<your-service>.onrender.com
  ```

A seed **replaces the whole knowledge base**. The new chunks are saved first, and then every chunk that wasn't in this seed is deleted. The response reports both counts, for example `{"inserted": 10, "removed": 4}` the first time the profile documents replace the old store documents. If embedding or saving fails, nothing is deleted. If only the deletion fails, run the same seed again.

Without the token or a signed-in session, `/seed` returns `401`, and `/admin` redirects to the sign-in page. Everything else (`/chat`, `/answer`, `/healthz`, `/documents`) is public. The chat page has no editor and no link to `/admin`.

## 5. Ask a question

```bash
curl -X POST https://<your-service>.onrender.com/answer \
  -H "Content-Type: application/json" \
  -d '{"query": "Who is Kai?"}'
```

`debug.answer_mode` in the response tells you how the answer was produced:

| `answer_mode` | Meaning |
|---|---|
| `generated` | Gemini wrote the answer from the retrieved passages |
| `extractive` | The chat model was unavailable (e.g. free quota used up), so the best-matching passages are returned with citations |
| `no_results` | Nothing relevant was found. Seed the knowledge base first |
| `error` | The question couldn't be searched (e.g. the embedding quota is used up). Try again later |

## 6. Optional: Datadog Agent Observability (free)

[Datadog Agent Observability](https://www.datadoghq.com/product/llm-observability/) (formerly LLM Observability) records each question as a trace. One trace shows the question, the embedding request, the passages found with their scores, the prompt and answer from Gemini, token counts, timings, and the outcome (`answer_mode`). Each seed is a trace too. Tracing is **off until you add a Datadog API key**, and the app works the same without it.

The app sends traces straight to Datadog, so no Datadog Agent runs beside it. That's what makes it work on Render's free plan.

**Free plan limits:** $0, up to **40K LLM spans a month**, and traces are kept for **15 days**. Only the chat model call counts as an LLM span, once per question that reaches the model. Embedding, search and seeding spans don't count. Gemini's free daily quota runs out long before 40K.

### Turn it on

1. **Create a Datadog account** at [datadoghq.com](https://www.datadoghq.com) ("Get started free"). Use the free offering. **If Datadog asks for a credit card or other payment method at any point, stop:** tracing is optional, and nothing else in this guide needs it.
2. **Choose a site.** Datadog asks for a region (site) at sign-up. Any site works. **AP1 (Japan)** is nearest to the Singapore service. Your site is in the address bar after you sign in:

   | Address after sign-in | `DD_SITE` |
   |---|---|
   | `app.datadoghq.com` | `datadoghq.com` |
   | `us3.datadoghq.com` | `us3.datadoghq.com` |
   | `us5.datadoghq.com` | `us5.datadoghq.com` |
   | `app.datadoghq.eu` | `datadoghq.eu` |
   | `ap1.datadoghq.com` | `ap1.datadoghq.com` |
   | `ap2.datadoghq.com` | `ap2.datadoghq.com` |

3. **Create an API key:** **Organization Settings → API Keys → New Key**. Copy it. Treat it like a password and never commit it.
4. **Give both values to the service:**
   - **New service:** when you create the Blueprint (step 3), Render asks for `DD_API_KEY` and `DD_SITE`. Fill them in, or leave them empty to keep tracing off.
   - **Existing service:** open **yt-rag → Environment**, add `DD_API_KEY` and `DD_SITE` (**Add Environment Variable**), and save. Saving redeploys the service. Render doesn't ask for variables added to `render.yaml` after the Blueprint was created.

   After the deploy, the Render log shows `Datadog Agent Observability tracing is on: site=…, app=yt-rag`.
5. **Ask a question** on the chat page.

### Find a trace

- In Datadog, open **LLM Observability → Traces** (the product is now named Agent Observability, so the menu label may differ). Filter by application `yt-rag`. Traces are tagged with `env:production` and the deployed commit as `version`.
- **From a log line:** each question writes one line to the Render log, such as `Answer finished: mode=extractive latency=31250ms citations=4 trace_id=…`. Search for that `trace_id` in the Traces view to open that question's trace.
- A failed step is marked as an error with the error type and HTTP status, for example `RateLimitError (HTTP 429)`. The provider's error message is never sent.

### Answer checks

Each question's trace also carries a few checks of the answer the visitor got. The app computes them from the answer itself, with no extra model calls. They aren't LLM spans, so they don't count toward the free plan's limit. They hold only numbers and true/false values, never question or answer text.

| Check | What it tells you | Recorded for |
|---|---|---|
| `retrieval_top_score` | The highest similarity score among the passages found (0 to 1). A low score means the knowledge base had nothing close to the question. | `generated` and `extractive` answers |
| `cites_sources` | Whether the answer cites at least one passage. `false` is expected for greetings, off-topic questions and "Kai's profile doesn't cover that". | `generated` answers |
| `citations_valid` | Whether every `[chunk_id]` in the answer names a passage the model was given. **fail** means the model made up a citation. | `generated` answers |
| `plain_text` | Whether the answer is free of Markdown (`**`, backticks, `#` headings), as the assistant's instructions require. **fail** means it isn't. | `generated` answers |

Answers with `answer_mode` `no_results` or `error` carry no checks.

**Where to find them:** open a trace and select its root span, `answer_question`, then its **Evaluations**. To look across many answers, filter traces by an evaluation in Agent Observability, for example every `citations_valid` that failed. Datadog is renaming the product, so menu names may differ.

The checks are part of tracing, so turning tracing off (next section) turns them off too. To measure answers *before* a change ships, run the offline evaluation in the [README](README.md#-evaluating-answers).

### What is sent, and how to turn it off

- **Sent by default:** the visitor's question, the retrieved passages, the prompt sent to the model (including the system prompt), and the answer. Datadog keeps them for 15 days. These questions already go to Gemini's free tier.
- **Never sent:** API keys, `SEED_TOKEN`, the admin session cookie, or any request header.
- **Metadata only:** set `OBSERVABILITY_CAPTURE_TEXT=false`. Traces then show text lengths, chunk IDs, scores, titles, model, timings, token counts and outcomes, but no question, passage, prompt or answer text.
- **Tracing off:** set `OBSERVABILITY_ENABLED=false`, or clear `DD_API_KEY`. Either way it takes effect on the next deploy, with no code change.
- **Cost estimates:** Datadog may show an estimated cost per call at the model's list price. On Gemini's free tier, nothing is billed.

To trace a local run, put `DD_API_KEY` and `DD_SITE` in your `.env` (see the Datadog block in [`.env.example`](.env.example)). The tests never send traces, even with a key in `.env`.

## Good to know

- **Cold starts.** A free Render service sleeps after 15 minutes without traffic. The next request wakes it in about a minute; the browser shows a loading page, and the CLI or curl may time out, so retry. Render can also restart free services at any time.
- **Free-tier quotas.** Gemini limits requests per minute and per day. Seeding the 10 default documents takes one embedding request. When the chat quota runs out, answers fall back to `extractive`.
- **Supabase pausing.** Free projects pause after a period of inactivity. Resume yours from the Supabase dashboard.
- **Changing settings later.** Render asks for the secrets only when the Blueprint is first created. To change a key or model later, edit it in **yt-rag → Environment**. Saving redeploys the service.
- **Switching the embedding model.** Vectors from different models can't be compared. After changing `OPENAI_EMBED_MODEL`, seed **all** documents again (a seed replaces the whole knowledge base).
- **Embedding size.** The database column is `VECTOR(1536)`, so `EMBEDDING_DIMENSIONS` must stay `1536`. Longer vectors from the model are shortened and re-normalized automatically.

## Running locally with Gemini

Copy the Gemini block from [`.env.example`](.env.example) into your `.env`, add your Supabase values, then:

```bash
uvicorn main:app --reload --port 8000
```

## Paid alternative: Google Cloud Run

The same image runs on Cloud Run, but that needs a Google Cloud project with billing enabled. Deploy with `gcloud run deploy yt-rag --source . --allow-unauthenticated`, and set the same environment variables as `render.yaml`, including your own `SEED_TOKEN`.
